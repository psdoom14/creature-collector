> Last updated: 2026-11-17, after Phase 7 of [docs/PLAN.md](docs/PLAN.md).
> Repo: `github.com/psdoom14/creature-collector` (private). Stack: Python 3.11+ (developed on 3.14), Pygame 2.6, JSON data.

## 1. What this is

A college OOP project: a small GBA-style creature-collecting demo. The playable path:
1. Title screen.
2. Professor intro and name entry.
3. Choose a starter in the lab; the rival takes the counter type.
4. Route 1: wild creatures, a trainer, and the rival battle.
5. Brookhaven City: the Healing Center.
6. Brookhaven Gym: leader WREN, who gives the GALE BADGE.

The rest of the documentation:
- **[README.md](README.md):** how to run and play.
- **[docs/OOP.md](docs/OOP.md):** the four pillars with line links, design patterns and UML.
- **[docs/PLAN.md](docs/PLAN.md):** the original code review (bugs B1–B14 and design flaws) and a log of what each phase changed.
- `docs/visual_audit.md` and `docs/prompt_draft.md`: earlier planning notes from before the rebuild, kept for history. Their findings are all addressed.

## 2. Rules not to break

1. **No pygame in `src/model/`.** A test fails if it appears.
2. **Game content lives in `data/`:**
   - species, moves, items and the type chart
   - encounter tables
   - maps (`data/maps/*.json`) and the start location (`data/world.json`)
3. **The model returns results; the UI draws them.** `Battle` returns `BattleEvent`s. `Explorer.step()`, `interact()` and `spotted_by()` return what happened, and the overworld animates it.
4. **Native resolution is 240×160**, scaled 3× to the window. Draw text with `draw_fitted_text()` / `wrap_text()` from `src/ui/components.py`; the tests fail if any text overflows its box.
5. **New behaviour goes in a subclass or a hook, not an `isinstance` check.** Examples:
   - a new item type overrides `use_in_battle()`
   - a new NPC type overrides `interact()`
   - a new battle type overrides `_on_opponent_fainted()`

## 3. Where things are

| Need to change… | Look in |
|---|---|
| Damage, turn order, catching, switching, XP | `src/model/battle.py` |
| What a trainer or gym leader does | `src/model/entities.py` (`TrainerNPC`, `RivalTrainer`, `GymLeader`) |
| Opponent move choice | `src/model/battle_ai.py` |
| Walking, warps, line of sight, encounters | `src/model/world.py` (`Explorer`) |
| Story progress (flags, starter, rival) | `src/model/story.py`, `GameState.flags` |
| A map's layout, people, trainers, doors | `data/maps/<map>.json` (rows of characters + a legend) |
| Tile art drawn in code | `src/ui/world_renderer.py` (`TileArt._paint_<tile>`) |
| A screen | `src/ui/<name>_scene.py` |

The map JSON files were generated by a helper script that isn't in the repo; edit the JSON directly. `tests/test_world.py` walks the whole world from the start tile and checks that every map and the nurse can be reached and every warp lands safely, so it will catch a broken map.

## 4. Balance

The gym was tuned by simulating playthroughs (about 12 wild battles, then the trainers and the gym, healing in between). Approximate win rates against WREN:
- Charmander: about 90%
- Squirtle: about 80%
- Bulbasaur alone: 0%. Grass is weak to Flying, so these players need a second creature; a rare Pikachu (10%) was added to Route 1 for that, and the NPC IVY hints at it. With one, about 95%.

Levels are in `data/maps/brookhaven_gym.json` and `route_1.json`.

## 6. Environment notes

- Headless runs (tests, scripts): set `SDL_VIDEODRIVER=dummy`. The test files set it themselves.
- `pygame.font` under Python 3.14 had a circular import with `sysfont`. It was patched locally in `~/.local/lib/python3.14/site-packages/pygame/font.py`, and `src/ui/components.py` falls back to an embedded bitmap font if a TTF can't load.
- `python3 scripts/capture_stages.py` regenerates `screenshots/` and works from any folder.
